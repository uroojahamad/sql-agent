# Database layer

This directory is the server-only data-access layer for the SQL agent.

## Responsibilities

- `prisma/schema.prisma` defines the three business tables and relations.
- `prisma/migrations` is the committed PostgreSQL migration history.
- `prisma/seed.ts` inserts a deterministic 30-row development data set into each table.
- `generated/prisma` is generated by Prisma and must not be manually edited.
- `client.ts` owns the singleton Prisma Client configured for Neon's pooled endpoint.
- `repositories` contains bounded, application-oriented database operations.
- `query-tools.ts` validates untrusted agent inputs before calling repositories.
- `ai-tools.ts` defines the six allowlisted AI SDK tools and safe execution logging.
- `sql-agent-prompt.ts` owns the server-only grounding and response policy.
- `evaluations` contains the opt-in real-model evaluation suite.

## Rules

- Import database access only from server-side modules.
- Prefer repository functions and explicit `select` clauses.
- Use tagged `$queryRaw` only for reporting calculations Prisma cannot express.
- Never use `$queryRawUnsafe` or `$executeRawUnsafe` with agent input.
- Use `npm run db:migrate:dev` only against development databases.
- Use `npm run db:migrate:deploy` for shared and production environments.
- Use `npm test` for deterministic tool-contract tests.
- Use `npm run test:database` for Neon integration tests.
- Use `npm run test:agent` intentionally; it calls Gemini and consumes model quota.
